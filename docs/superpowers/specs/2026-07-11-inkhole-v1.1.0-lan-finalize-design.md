## 三、文件夹传输设计

### 决策
**发送端 zip 流式打包，接收端存为 `.zip`。三端接收端零改动。仅桌面端（Win/Mac）支持发送目录。**

理由：
- 符合项目「简化优先、安全优先」哲学——不在接收端做自动解压，彻底规避 zip-slip 路径穿越。
- 复用现有 `send_file` 全套通道（加密 / 进度 / ACK / 分块 WHE2），接收端把它当普通文件处理。
- Android 接收端一行不改；发送端本轮不做，降低风险面。

### 发送端流程（`pet.py` + `mainwindow.py`）
1. 拖入路径判定：`os.path.isdir(path)` → 走打包分支；`os.path.isfile(path)` → 原有分支。
2. 打包：`zipfile.ZipFile` 递归写入目录内容到**临时目录**（`tempfile.mkdtemp`）下的 `<目录名>.zip`。
3. 入队：把临时 zip 路径交给 `SendQueue`，复用现有发送逻辑。
4. 清理：该文件发送完成后删除临时 zip（发送成功或失败都删）。

### 接入点
- **桌宠 QML**：`bridge.dropFile` 目前 `if path and os.path.isfile(path)` 才入队。改为同时接受目录。
- **主窗口**：`MainWindow.dropEvent` 目前对每个 url 调 `self._bridge.dropFile(url.toString())`；`_pick_and_send` 走 `QFileDialog.getOpenFileNames`（只能选文件）。
  - `dropEvent`：目录也放行。
  - 可选增强：`_pick_and_send` 旁边加一个「发送文件夹」入口（`QFileDialog.getExistingDirectory`）。本轮以拖拽为主，按钮入口视界面空间决定。

### 边界与错误处理
- **空目录**：仍打包成空 zip 正常发送（行为可预期），或提示「目录为空」——实现时取「照常发送空 zip」，避免特判分叉。
- **打包失败**（权限 / 磁盘满）：不入队，`status` 提示「打包失败：<原因>」。
- **大目录**：先落地临时 zip 再发；加密走现成 WHE2 分块，内存恒定。临时盘空间不足由 `zipfile` 抛错，归入「打包失败」。
- **符号链接**：`zipfile` 默认跟随写入内容，不额外处理（局域网自用场景可接受）。
- **命名**：临时 zip 名 = `<目录basename>.zip`；接收端经 `_safe_filename` + `_unique_path`，同名不覆盖。

### 测试（TDD，先测后写）
纯函数化打包逻辑，抽成可单测的辅助函数（如 `_zip_dir(src_dir) -> tmp_zip_path`），在 `tests/test_p2p.py` 或新增 `tests/test_folder.py` 覆盖：
- 目录→zip→解压往返内容一致（含子目录、中文名、空文件）。
- 空目录打包不报错。
- zip 经 `send_file` 端到端送达（复用现有测试脚手架）。
- 临时文件发送后被清理。

## 六、执行顺序（严格按序，每步是下一步前提）

1. **回归测试**：`make test`，确认安全加固未破坏引擎（85 项基线）。
2. **真机验证新界面**：本机（Windows，有 GUI）起 `PYTHONPATH=src python -m inkhole.pet`，确认主窗口显示、设置页读写、拖拽/点击发送、托盘「打开主界面」可用。由执行者（本会话）在本机完成。
3. **文件夹传输（TDD）**：先写打包/往返测试 → 实现 `_zip_dir` + dropEvent 判定 → 接 UI → 测试全过。
4. **提交**：拆成清晰 commit——①界面重构（mainwindow + pet 瘦身）②安全加固（p2p）③文件夹传输。
5. **文档 + bump**：按第五节更新三处文档 + 版本号到 v1.1.0。
6. **Mac 发布**：打 `v1.1.0` tag → GitHub Actions `package.yml` 自动并发构建 Win/Mac 并发布到 Release。
7. **推 GitHub**：走 `http://127.0.0.1:7897` 代理（抖动重试）。

## 八、风险与缓解

| 风险 | 缓解 |
|------|------|
| 界面重构动了核心交互却从未运行 | 执行第一优先级是跑测试 + 真机验证，再叠新功能 |
| Mac 上 Acrylic 磨砂不可用 | `mainwindow.py` 已有 `sys.platform == "win32"` 守卫，非 Win 回退不透明深色；CI 在 macos-latest 构建可验证能否加载 |
| 临时 zip 泄漏（发送失败未清理） | 发送完成回调里 finally 删除；`SendQueue` 单文件结束即清 |
| 文档/行为不一致遗留 | 第五节列为强制项，纳入验收标准 |
| 大目录打包耗时阻塞 UI | 打包在发送队列的工作线程里做，不在 UI 线程 |
