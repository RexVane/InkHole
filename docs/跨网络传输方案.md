# Cross-network transport

InkHole 2.0 has one transport implementation. The Rust `inkhole-core` crate
owns LAN discovery, direct transfer, one-time codes, and SSH relay sessions.
The desktop and mobile hosts only render state and forward JSON requests.

## Routes

1. LAN discovery announces a signed Ed25519 device record through UDP/mDNS.
   Peers are deduplicated by `instance_id` and may advertise multiple IP
   addresses.
2. A direct connection uses Quinn QUIC. The peer certificate is pinned to the
   signed discovery fingerprint, then the optional shared secret authenticates
   the request with a BLAKE3 MAC.
3. If a direct route is unavailable, the sender can create a one-time code.
   Magic Wormhole provides PAKE rendezvous and an encrypted transit path; file
   bytes still use the InkHole streaming protocol and never land on the relay.
4. An SSH relay is an explicitly configured long-lived route. Host keys are
   checked against the configured `SHA256:` fingerprint before forwarding.
   Devices pair their relay identity with PAKE before the data channel starts.

## File protocol

Every file and folder is streamed in bounded frames. A folder begins with a
signed, sorted manifest that includes relative paths, directory entries, file
sizes, modification times, and a BLAKE3 digest. Receivers reject traversal,
duplicate, symlink, and type-confusion entries before creating any output.

Data is written to a temporary path and atomically committed only after the
final BLAKE3 digest and completion receipt match. Each transfer has a durable
checkpoint, a cancellation token, and a resumable offset. A cancelled or
interrupted transfer cannot be reported as successful.

## JSON service boundary

The host-facing methods are implemented by `JsonService`:

```text
lan.start / lan.refresh / lan.send / lan.send.cancel / lan.stop
wormhole.create / wormhole.join.start / wormhole.accept / wormhole.reject
ssh.listen / ssh.pair.create / ssh.pair.join / session.cancel
```

Desktop calls the service directly from Tauri. Flutter keeps one FFI service
handle in a dedicated isolate and polls the same event queue. No Go, Python,
Kotlin, gomobile, or loopback sidecar is part of the 2.0 protocol.
