# 墨洞跨网络传输方案（v1.5.4）

墨洞保留局域网发现和 Tailscale 手动直连，并增加两种不要求两端处于同一虚拟局域网的方式：一次性短码和 SSH VPS 中继。三种方式最终都复用同一套 WHPP/WHF1 文件协议，因此文件名、文件夹结构、加密、进度、取消、强制 ACK/SHA-256、断点续传和崩溃恢复行为在 Windows、macOS、Android 上一致。接收端使用 `transfer_id` 检查点、提交日志和完成回执形成同一套发布事务，跨网连接方式不会改变成功判定。

| 方式 | 适用场景 | 是否长期在线 | 需要填写 |
| --- | --- | --- | --- |
| Tailscale | 自己的固定设备，优先点对点 | 是 | 对方 Tailscale IP/MagicDNS、监听端口 |
| 一次性短码 | 临时给另一台设备发送 | 否 | 接收端只输入短码，或扫描二维码 |
| SSH 中继 | 自有 VPS、固定设备长期互传 | 是 | VPS 地址、SSH 端口、用户名、已有私钥 |

## 一次性短码

发送端先选择一个或多个文件，墨洞向 Magic Wormhole 配对服务登记一次性短码。接收端输入短码后先看到设备名、文件数、总大小和文件名摘要，确认后才建立通道。

短码通过 SPAKE2 完成 PAKE 安全配对。配对服务只负责会合；数据优先直连，无法直连时使用加密 Transit 中继。墨洞使用自己的 AppID：

```text
com.rexvane.inkhole/transport-v1
```

文件不使用 Magic Wormhole 自带的 ZIP 传输。建立加密连接后，墨洞在一条 Wormhole 会话上运行 yamux；每个文件或文件夹使用独立流，流内仍是 WHPP/WHF1。多文件不需要先合成 ZIP，也不需要在中继落盘。

## SSH VPS 中继

每台设备使用 SSH 私钥登录 VPS，并申请只监听 VPS 回环地址的反向端口。配对码包含远端端口和一次性词组；两端通过该端口运行 SPAKE2，交换设备身份和 Noise 公钥。配对成功后，设备列表长期保存，对端离线时 SSH 会自动重连。

VPS 要求：

- 有可访问的 SSH 服务和公网 IP/域名。
- 用户已配置公钥登录，`sshd` 允许 TCP forwarding。
- 不需要部署墨洞服务、数据库或对象存储。
- 不需要开放新的公网业务端口；反向端口只绑定 `127.0.0.1`。

应用只允许选择私钥文件或粘贴已有私钥，不生成 SSH 密钥。桌面端把粘贴私钥、私钥口令和 Noise 私钥保存到系统凭据存储；Android 使用 Android Keystore 加密保存。选择文件模式只保存文件路径或 SAF URI，使用时再读取。

配对后的数据连接使用 Noise IK 验证双方固定公钥。默认开启外层端到端加密，此时 VPS 管理员看不到文件内容；关闭单个设备的“外层加密”后，SSH 链路仍加密，但 VPS 管理员可能读取转发后的内容和元数据。

## 共享核心和边界

`transport-core` 是桌面和 Android 共用的 Go 模块：

```text
Windows/macOS UI -> JSON sidecar -> transport-core
Android UI       -> gomobile AAR -> transport-core
transport-core   -> 已认证 loopback 端点 -> WHPP/WHF1 节点
```

发送端连接本机端点前必须发送 `IKAT + 随机能力令牌`；共享核心回注接收节点前必须发送 `IKCI + 节点令牌`。令牌只存在于进程内，不广播、不持久化，避免本机其他进程直接借用隧道端点。

## 名称说明

Magic Wormhole 和 `wormhole-william` 都是已有开源项目名称，不是墨洞的自定义命名。墨洞维护了一个本地 `wormhole-william` 源码分支，用于原始加密隧道、HTTP CONNECT 代理和连接可靠性修复。墨洞自己的部分包括专用 AppID、共享传输核心、SSH/PAKE/Noise 组合、loopback 令牌，以及 WHPP/WHF1 文件传输。
