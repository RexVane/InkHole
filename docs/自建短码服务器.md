# 自建短码服务器（rendezvous + 中继）

短码默认使用 magic-wormhole 官方公共服务器（`relay.magic-wormhole.io` 配对、
`transit.magic-wormhole.io:4001` 中继），服务器在海外：国内访问单程延迟高
（配对要串行多次往返）、带宽小且不稳定。两台设备都无公网 IPv6 时全部流量
走中继，速度直接由中继决定。

在自己的 VPS 上部署这两个服务后，配对延迟和中继带宽都由你的服务器决定，
跨网络速度可提升一个数量级。短码协议用 SPAKE2 端到端加密，服务器只能看到
加密流量，自建或公共服务器都无法解密内容。

## 部署（Docker Compose）

```yaml
# docker-compose.yml
services:
  mailbox:
    image: python:3.12-slim
    command: >
      sh -c "pip install --quiet magic-wormhole-mailbox-server &&
             twist wormhole-mailbox --port tcp:4000"
    ports:
      - "4000:4000"
    restart: unless-stopped

  transit:
    image: python:3.12-slim
    command: >
      sh -c "pip install --quiet magic-wormhole-transit-relay &&
             twist transitrelay --port tcp:4001"
    ports:
      - "4001:4001"
    restart: unless-stopped
```

```bash
docker compose up -d
# 防火墙放行 TCP 4000(配对)与 4001(中继)
```

不用 Docker 的话，`pip install` 上述两个包后分别运行
`twist wormhole-mailbox --port tcp:4000` 和 `twist transitrelay --port tcp:4001`
（可配 systemd 常驻）。

## InkHole 配置

桌面端与手机端的设置里各有两项，**两端必须填一致**：

| 设置项 | 值 |
| --- | --- |
| Rendezvous 服务器 | `ws://你的服务器:4000/v1` |
| Transit 中继 | `你的服务器:4001` |

留空则回到官方公共服务器。`ws://` 明文仅承载 SPAKE2 加密后的配对消息，
内容安全不受影响；介意元数据的话可用 nginx 反代加 TLS 后填 `wss://`。

## 效果参考

- 配对（输码到弹确认）：官方服务器国内典型 3-6 秒，自建国内 VPS 约 1 秒内。
- 中继吞吐：2026-08 实测从国内家宽经官方中继仅 **0.03-0.2 Mbps**
  （裸 TCP 与应用同样慢，链路本身即瓶颈）；自建等于 VPS 出口带宽。
- 双方有公网 IPv6 时会自动直连（v2.0.10+），不经过中继，此时中继只兜底。
