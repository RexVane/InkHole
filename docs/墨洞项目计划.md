# InkHole 2.0 migration status

This file records the completed technology migration. The user-facing layout,
desktop pet, file selection flow, received-file list, short-code dialogs, SSH
settings, and configuration labels remain unchanged.

## Completed

- Rust 1.93 workspace with Tokio asynchronous services.
- Quinn QUIC direct LAN transport with signed discovery and certificate pinning.
- BLAKE3 verification for files, folders, manifests, and resumable checkpoints.
- Magic Wormhole short-code sessions and SSH relay/pairing in the same core.
- Tauri 2 desktop host with the existing web frontend and floating pet window.
- Flutter mobile host with an isolate-owned Rust FFI service.
- Cancellation, progress events, folder manifests, atomic commits, and tests.
- CI and release workflows now build Rust/Tauri and Flutter artifacts.

## Deliberate compatibility boundary

Version 2.0 does not read the old Python, Go, gomobile, Wails, Kotlin, or
desktop configuration formats. A new identity and configuration are generated
on first launch. This avoids carrying two protocol implementations or silently
accepting files produced by the obsolete transport.

## Verification

The Rust workspace is checked with `cargo fmt`, `cargo clippy -D warnings`, and
`cargo test --workspace`. Flutter analysis and Android/iOS builds require a
Flutter SDK, Dart SDK, Android NDK, or Xcode on the host running the check.
