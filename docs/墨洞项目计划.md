# 墨洞(InkHole)文件传输 —— 项目计划与进度

> 最后更新：2026-07-04
> 一句话目标：把文件拖进桌面或手机上的「墨洞」，文件自动出现在另一台设备上。

## 总体设计

- 网络环境：**同一局域网**（两台设备连同一 WiFi/路由器，mDNS 自动发现）
- 传输方式：**P2P 直连**（mDNS 发现 + TCP 直传，无需服务器）
- 平台：**Windows / macOS / Android 三端互通**
- 加密：可选 AES-256-GCM 端到端加密（口令两端一致）

架构（两层解耦）：

```
   电脑A / Android                              电脑B / Android
┌──────────────┐    mDNS 自动发现     ┌──────────────┐
│ 墨洞桌宠/App  │ ──────────────────> │ 墨洞桌宠/App  │
│  (拖入/发送)  │    TCP 直连传输      │  (收到文件)   │
│              │    WHPP 协议         │              │
└──────────────┘    双向互传           └──────────────┘
   面子:桌宠(QML动画+拖拽) / Compose UI
   里子:P2P引擎(mDNS+TCP直连+WHE2加密)
```

## 已完成 ✅（2026-07-03：P2P 引擎 + 桌面桌宠）

- [x] **P2P 引擎 `p2p.py`**：mDNS（zeroconf）注册 `_inkhole._tcp.local.` + TCP 直连；WHPP 协议；手动选目标设备，离线清空选中不自动切换；可选端到端加密（复用 crypto.py）；命令行入口。
- [x] **加密模块 `crypto.py`**：AES-256-GCM，PBKDF2-HMAC-SHA256（10 万次迭代）密钥派生；WHE1 整块格式（小文件）。
- [x] **桌宠挂件 `pet.py` + `inkhole.qml`**：PySide6+QML，黑洞造型，拖文件触发吸入/吐出动画，右键菜单发送目标子菜单，开机自启（Windows/macOS/Linux）。
- [x] **测试 `test_p2p.py`**：7 组 28 项，TCP 直连/加密/设备切换/离线/回调/多文件/路径穿越。
- [x] **修复 Windows 端口绑定 bug**：`bind(("", 0))` 让 OS 自动分配唯一端口，防两节点同机分到同一端口。

- [x] 内部标识全量更名：Python 包名 `inkhole`，mDNS 服务类型 `_inkhole._tcp`，Android 包名 `com.rexvane.inkhole`，类名/文件名/配置路径全部同步。与 v1.0.0 不互通。

### 引擎第二轮
- [x] **WHE2 分块加密**：>32MB 加密文件走 4MB 分块流式 AES-GCM，块序号进 nonce+AAD（防篡改/重排），收发内存峰值恒定 4MB。≤32MB 保持 WHE1 整块。
- [x] **ACK 回执**：header 加 `want_ack`，接收方落盘后回 1 字节；发送方能感知解密失败/磁盘问题；向后兼容老版本。
- [x] **传输进度**：`on_progress(kind, name, done, total)` 回调，节流 0.25s；桌宠/Android 同步显示百分比。
- [x] **发送队列**：桌面拖 N 个文件串行排队，批量完成聚合提示"已吞入 k/N"。
- [x] **仅接收目标设备（trusted_only）**：只接受选中设备 IP 的连接，桌面右键勾选+配置持久化，Android 设置开关。
- [x] **多网卡/VPN**：mDNS 宣告全部本机 IPv4（默认路由优先），对端逐地址尝试连接。
- [x] **拒收 drain**：拒收时先消化对端已发数据（上限 8MB）再回执关闭，ACK_FAIL 不被 RST 冲掉。

## 已完成 ✅（2026-07-04：可靠性与安全修复）

- [x] **半截文件不落盘**：`remaining==0` 才原子 `os.replace` 改名，否则删 `.part`（桌面+Android）。
- [x] **恶意 size 拒收**：非整数/负数/超 1TB 拒收；磁盘余量不足（<256MB）拒收。
- [x] **mDNS 名字冲突根治**：服务名带 8 位唯一实例 ID；TXT `instance_id` 做自我过滤；离线按服务名精确匹配；显示名撞名加 " (2)" 后缀。
- [x] **Android NSD 稳定性**：resolve 串行队列；`stop()` 注销加 try-catch；`onServiceRegistered` 记录系统实际注册名。
- [x] **设置持久化**：桌面 `config.json`（Win `%APPDATA%\InkHole`，Mac `~/Library/Application Support/InkHole`）；Android `SharedPreferences("inkhole")`；CLI 参数改一次记住。
- [x] **前台服务**：Android P2P 节点挪进 `InkHoleService`，锁屏/切后台不断线。
- [x] **系统分享入口**：Android ACTION_SEND/ACTION_SEND_MULTIPLE，任意 App 分享→墨洞。
- [x] **收件箱可见**：收到的文件导出到系统 `Downloads/InkHole`（MediaStore），系统通知可点击打开。
- [x] **Windows 默认收件箱**：`SHGetKnownFolderPath` 查询真实桌面，兼容 OneDrive 重定向。
- [x] **打包/CI 修复**：产物 ASCII 命名（`InkHolePet.exe` / `InkHole-v2.0.0.apk` / `InkHolePet-macos.zip`），三端分开发布。
- [x] **测试**：17 组 66 项全通过（兼容 pytest）。

## 快速命令备忘

```bash
# 测试 P2P 引擎（无需 GUI）
make test
# 或
PYTHONPATH=src python3 tests/test_p2p.py

# 起桌宠
PYTHONPATH=src python -m inkhole.pet
PYTHONPATH=src python -m inkhole.pet --name 我的电脑 --secret 加密口令

# 命令行版 P2P（无 GUI，监视发件箱）
PYTHONPATH=src python -m inkhole.p2p \
    --inbox ~/InkHole/收件箱 --outbox ~/InkHole/发件箱

# 打包
cd packaging && build-windows.bat        # → packaging\dist\InkHolePet.exe
cd packaging && bash build-mac.sh        # → packaging/dist/InkHolePet.app

# Git push（需走 Clash 代理）
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push
```
