# 墨洞(InkHole)文件传输 —— 项目计划与进度

> 最后更新：2026-07-04
> 一句话目标：把文件拖进桌面上的「墨洞」桌宠，文件自动出现在另一台设备上。
> 2026-07-04 更名：原名 Wormhole/虫洞与 wormhole.app、magic-wormhole 等多个现有传输工具重名，改名**墨洞 InkHole**。内部标识(Python 包名/mDNS 服务类型/Android 包名)保留 wormhole 不动，保证新旧版本协议互通与升级安装不断链。

## 总体设计（已定稿）

需求选择（已和自己确认）：

- 网络环境：**同一局域网**（两台电脑连同一 WiFi/路由器，mDNS 自动发现）
- 传输方向：**双向互传**（任意一台拖入，另一台都收到）
- 实现方式：**P2P 直连**（mDNS 发现 + TCP 直传，无需服务器）
- 文件落点：**固定的「虫洞收件箱」文件夹**（默认 `~/Wormhole/收件箱`，可配置）
- 桌宠形态：**黑洞吞噬感 + 乳白色吸积盘 + 桌面小图标大小（低调）**

架构（两层解耦）：

```
   电脑A                                      电脑B
┌──────────────┐    mDNS 自动发现     ┌──────────────┐
│ 虫洞桌宠       │ ──────────────────> │ 虫洞桌宠       │
│  (拖入文件)    │    TCP 直连传输      │  (收到文件)    │
│ (吸入动画)    │ ──────────────────> │ (喷出动画)    │
│              │    WHPP 协议         │              │
│ 收件箱出现    │ <────────────────── │  拖入文件     │
└──────────────┘    双向互传           └──────────────┘
   面子:桌宠(QML动画+拖拽)  里子:P2P引擎(mDNS+TCP直连)  面子:桌宠
```

## 已完成 ✅（2026-07-03：P2P 迁移——去掉服务器依赖）

虫洞从 FTP 中转模式迁移为局域网 P2P 直连模式，不再需要架设任何服务器。

- [x] **新增 `p2p.py`**：P2P 引擎核心（约 350 行）。mDNS（zeroconf）注册 `_wormhole._tcp.local.` 服务 + ServiceBrowser 发现对端；WHPP 协议（magic + JSON 头 + 文件数据）TCP 直连传输；对端管理（手动选目标、离线清空选中不自动切换）；可选端到端加密（复用 crypto.py）；命令行入口（无 GUI 也能用）。
- [x] **新增 `crypto.py`**：把 AES-256-GCM 加解密抽取为独立模块，供 p2p.py 使用。
- [x] **`pet.py` 重写**：底层从 WormholeSync 换成 P2PNode。右键菜单新增「发送目标」子菜单，动态列出已发现设备（●选中/○未选），支持切换和取消。拖文件时无选中目标会提示「右键选择目标设备」且不播吸入动画。
- [x] **`wormhole.qml` 更新**：DropArea 的 onDropped 加 `bridge.hasTarget()` 判断，无目标时不播动画只显示提示。
- [x] **`sync.py` 已移除**：FTP 中转模式不再需要，`test_wormhole.py` 一并删除。crypto.py 保留供 p2p.py 使用。
- [x] **修复 Windows 端口绑定 bug**：Windows 上 `SO_REUSEADDR` 允许两个 socket 绑同一端口（不像 Unix 只允许 TIME_WAIT 重用），导致同机测试时两个节点分到同一端口、只有一方能收到连接。改为 `bind(("", 0))` 让 OS 自动分配唯一端口。
- [x] **测试**：`test_p2p.py` 7 组 28 项全通过（直连传输/加密/设备切换/对端离线/回调/多文件/路径穿越）。


## 已完成 ✅（2026-07-04：三端完整度大修——正确性/协议/体验）

### 正确性修复（三端）
- [x] **半截文件不落盘**：对端中途断连时，之前会把半截文件顶着完整文件名落盘、还会覆盖收件箱同名完整文件。现在 `remaining==0` 才原子改名，否则删 `.part`（桌面 p2p.py + Android WormholeNode.kt）。
- [x] **解密失败不落盘**：之前解密失败仍把密文 blob 当文件交付；现在拒收并回执失败。
- [x] **恶意 size 拒收**：header 来自网络不可信——非整数/负数/超 1TB 拒收；磁盘余量不足(<256MB)拒收。
- [x] **mDNS 名字冲突根治**：服务名带 8 位唯一实例 ID（`名字-a1b2c3d4`），两台同名设备不再撞名；TXT 属性 `instance_id` 做"不发现自己"判断（替代按显示名，显示名重名时旧逻辑会互相看不见）；离线事件按服务名精确匹配（旧逻辑显示名对不上会留幽灵设备）；显示名撞名自动加 " (2)" 后缀。与 v1.0.0 老客户端互通。
- [x] **Android NSD 修复**：`stop()` 注销加 try-catch（注册失败过会抛异常崩溃）；`onServiceRegistered` 记录系统实际注册名（冲突改名场景）；resolve 排队逐个执行（并发 resolve 报 FAILURE_ALREADY_ACTIVE，设备"时而发现不了"的元凶）；对端表 key 用发现时服务名（resolve 返回的转义可能不一致）。
- [x] **对端 IP 变化跟踪**：zeroconf `update_service` 重新解析并原地更新地址（DHCP 换租后不再连旧 IP）。
- [x] **Linux 自启修复**：.desktop Exec 里误写的 `&amp;&amp;` HTML 转义改回 `&&`。
- [x] **Windows 默认收件箱**：不再硬编码 OneDrive 路径，SHGetKnownFolderPath 查询真实桌面（含重定向），查不到回退 `~/Desktop`。

### 协议增强（WHPP，向后兼容 v1.0.0）
- [x] **ACK 回执**：header 加 `want_ack`，接收方处理完回 1 字节（0x01 成功/0x00 失败）。发送方能感知对端解密失败/磁盘问题；老对端读完即关连接，按成功处理，互通不受影响。

## 快速命令备忘

```bash
cd <项目目录>

# 测试 P2P 引擎（无需 GUI）
PYTHONPATH=src python3 tests/test_p2p.py

# 起桌宠（P2P 模式，需 PySide6 + zeroconf）
PYTHONPATH=src python3 -m wormhole.pet
PYTHONPATH=src python3 -m wormhole.pet --name 我的电脑 --secret 加密口令

# 命令行版 P2P（无 GUI，监视发件箱）
PYTHONPATH=src python3 -m wormhole.p2p \
    --inbox ~/Wormhole/收件箱 --outbox ~/Wormhole/发件箱

# 推送
git push
```
