# SSH 远程模式

墨洞的远程模式使用一台标准 OpenSSH 服务器连接不同网络中的设备。服务器无需
安装墨洞、Docker、Caddy、数据库或额外守护进程，也不需要开放 Web 端口。

局域网与远程模式严格二选一：

| 模式 | 发现 | 数据路径 | 服务器 |
|---|---|---|---|
| 局域网 | mDNS | 设备间 TCP 直连 | 不使用 |
| 远程 | SSH 账户中的短期登记 | 设备 -> SSH 服务器 -> 设备 | 标准 OpenSSH |

切换模式会停止旧引擎并清空目标设备；传输期间不能切换。

## 服务器要求

建议使用一台带公网 IP 的 Linux 云服务器，并创建专用于墨洞的普通用户。该用户
只需拥有可写的 home 目录，不需要 `root` 或 `sudo`。服务器必须支持：

- OpenSSH 公钥登录。
- SFTP 子系统。
- 本地和远程 TCP 转发，即 `AllowTcpForwarding yes`。
- 同一账户的多路并发 SSH 会话。

典型的 `sshd_config` 设置如下；多数发行版默认已经满足：

```text
PubkeyAuthentication yes
AllowTcpForwarding yes
GatewayPorts no
Subsystem sftp internal-sftp
```

`GatewayPorts no` 应保持关闭。墨洞申请的随机转发端口只绑定在服务器
`127.0.0.1`，不会暴露到公网。若服务器配置了 `DisableForwarding yes`、
`PermitOpen` 或 `PermitListen` 白名单，需要相应允许回环地址上的动态端口。

修改配置后先运行 `sshd -t` 检查语法，再按发行版重载服务：

```bash
sudo sshd -t
sudo systemctl reload sshd  # 部分 Debian/Ubuntu 系统服务名为 ssh
```

云安全组和系统防火墙只需放行 SSH 的 TCP `22` 或自定义端口。不要为墨洞开放
80、443 或随机高端口。

## 账户与私钥

为墨洞生成一把专用 OpenSSH 私钥，将公钥加入专用账户的
`~/.ssh/authorized_keys`。所有需要互相发现的设备必须填写：

1. 同一台服务器。
2. 同一个 SSH 用户名。
3. 同一份私钥文本，包括相同的私钥格式。

私钥用于 SSH 鉴权，同时派生设备登记和握手的组密钥。使用不同私钥的设备即使
能登录同一账户，也不会互相发现。建议不要复用日常运维私钥。

首次连接时，客户端会显示服务器主机密钥的 `SHA256:` 指纹。请先在云控制台或
可信终端核对，例如：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

桌面和 Android 都不会把 SSH 私钥或口令写入应用配置。它们只在当前进程内存中
用于维持和重连 SSH 会话；应用进程完全退出后，需要重新输入私钥。服务器地址、
用户名、端口、已确认的主机指纹和设备端 E2E 身份会保存在本机。

## 服务器上保存什么

每台在线设备在 SSH 用户 home 下写入：

```text
~/.cache/inkhole/peers/<device-id>.json
```

记录只包含设备 ID、显示名称、回环转发端口、P-256 公钥和 HMAC。客户端每 20 秒
刷新记录，超过 75 秒的记录会被其他客户端清理。文件名和文件内容不会写入服务
器磁盘；传输中断留下的客户端 `.part` 文件也会删除。

服务器终止 SSH 连接，因此可以观察账户、在线时间、设备登记和流量大小，但文件
流在 SSH 内仍使用独立的 P-256 ECDH + HKDF-SHA256 + AES-256-GCM 端到端加密，
服务器没有传输密钥。详见 [SSH 远程协议](relay-protocol.md)。

## 使用步骤

1. 在每台设备的设备栏切换到“远程”。
2. 填写服务器、公用 SSH 私钥；需要时在高级设置填写用户名、端口和私钥口令。
3. 核对并确认主机密钥指纹。
4. 等待其他使用同一账户和私钥的墨洞设备出现，选择目标后发送。

远程模式不提供离线暂存；发送方和接收方必须同时在线。

## 故障排查

- `服务器禁止 TCP 转发`：确认 `AllowTcpForwarding yes`，并移除冲突的 Match、
  `DisableForwarding`、`PermitOpen` 或 `PermitListen` 限制。
- `SSH 密钥鉴权失败`：确认用户名、私钥、公钥安装位置和私钥口令。留空用户名时
  桌面端会尝试常见云镜像账户。
- `看不到其他设备`：确认服务器、用户名和私钥文本完全一致，并确认两端应用都在
  远程模式且 SSH 会话已连接。
- `SFTP 不可用`：启用 OpenSSH SFTP 子系统并确保用户 home 可写。
- `主机密钥已变化`：不要继续连接；先确认服务器是否重装或遭到替换。
- `连接一段时间后掉线`：检查云服务器 SSH 空闲策略、防火墙会话超时和网络质量；
  客户端会以退避方式自动重连。
